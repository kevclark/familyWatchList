## What this is
An Android app that:
- Tracks what the family has watched (manually logged, not scraped)
- A profile creator should exist, name or group name, which may just be the persons name (and avatar) or family name.  If maximum number of profiles is needed for the app, make it 10.
- Pulls title metadata and platform availability from TMDB's free API
- Learns taste from logged history (genre/cast/crew/keyword affinity, recency-weighted)
- Surfaces a short weekly shortlist filtered to platforms we actually subscribe to (all the main ones in the UK, Netflix, Disney, Prime, BBC iplayer, Three and Four)
- The app must be polished and similar to browsing titles in other streaming apps, thumbnail viewer, when clicked movie description and stretch target, ability to watch trailer, i.e a user experience on par with the streaming apps themselves.

## Why this shape (context so you don't re-derive it)
- Netflix/Disney+/Prime etc. have no public API for personal watch history — that's a hard wall, not a token-budget problem. Manual logging sidesteps it entirely.
- TMDB's `/movie/{id}/watch/providers` and `/tv/{id}/watch/providers` endpoints (JustWatch-sourced, free, non-commercial) give per-region platform availability. Must attribute JustWatch per TMDB's terms.
- Recommendation logic is built entirely from our own logged data — no runtime LLM calls needed, no per-user ongoing API cost. This is a one-time build cost, not a recurring one.

## Platform decision
Android, not iOS. Reasons: no Mac/Xcode/Apple dev licence required, and I have a real Android device to sideload the APK directly to via wireless ADB. Build target is an installable APK, not a Play Store listing.
