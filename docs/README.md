# Family Watchlist documentation

Start here. Everything in this folder describes how the app is built and why. For what the app
does, see the [project README](../README.md).

## Read in this order

| If you want to... | Read | What it is |
|---|---|---|
| Understand how the app fits together | [ARCHITECTURE.md](ARCHITECTURE.md) | Parts, data model, the key flows as diagrams, and where each rule is enforced in code. |
| Know why something works the way it does | [adr/](adr/README.md) | Architecture decision records, one per significant choice, with status and source. |
| See what is tested and what is not | [TESTING.md](TESTING.md) | Tests grouped by area, the rule or bug each one pins, and the known gaps. |
| Run the app on an emulator or a phone | [PREVIEW.md](PREVIEW.md) | Emulator boot flags, scrcpy mirroring and wireless ADB. |
| See how big the codebase is | [CODE_STATS.md](CODE_STATS.md) | Line counts by language and component, regenerated by `tools/code_stats.py`. |

## Outside this folder

- [`PLAN.md`](../PLAN.md): the approved spec (data model, TMDB integration, recommender, screens,
  milestones). Where it and the code disagree, ARCHITECTURE.md lists the gaps.
- [`PROGRESS.md`](../PROGRESS.md): the living checklist of what has shipped.
- [`CLAUDE.md`](../CLAUDE.md): working rules for the AI agents that build the app.

## Keeping these docs current

Docs travel with the code: any feature updates ARCHITECTURE.md, adds or updates an ADR (and the
index in `adr/README.md`) and updates TESTING.md in the same change.

The PNG files in this folder are screenshots taken while verifying each milestone, named by
milestone. They are evidence, not documentation.
